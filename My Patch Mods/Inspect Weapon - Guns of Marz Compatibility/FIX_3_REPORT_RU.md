# Fix 3 / 0.4.0 — технический отчёт

## Что подтвердил контрольный тест Fix 2

- live-счётчик магазина работает: число на кнопке и tooltip используют фактический `CurrentAmmoCount`;
- runtime-детали Guns of Marz читаются корректно: в логе отдельно видны `Scope`, `RailUp`, `Underbarrel`, `BayonetKnife`;
- на M1911 за один сеанс видно снятие PL-4, снятие/возврат Colt Mount и последующий возврат PL-4;
- на Mossberg 590 видно снятие JS14 и его возврат при сохранённой верхней планке;
- собственных stack trace от `GOM_InspectWeaponCompat` в контрольном логе не появилось.

## Почему снять можно было, а поставить обратно — нет

У оригинального Inspect Weapon два независимых ограничения:

1. Пустой attachment-слот открывает выбор только при наличии отвёртки. Поэтому без неё интерфейс просто не показывал список и выглядел как «ничего не происходит».
2. Оригинальный `addAttachmentButton` вызывает:
   `ISUpgradeWeapon:new(character, weapon, part, 50)`.
   В текущем Gunworks четвёртый аргумент уже означает `UniversalAttachment outcomeFullType`. Число `50` для прямой GoM-детали больше не является безопасным legacy time-аргументом.

Fix 3 прямые GoM WeaponPart ставит только через 3-аргументный вызов. Для универсальных планок четвёртый аргумент используется по назначению и содержит реальный зарегистрированный outcome type.

## Планки

Есть два случая:

- обычная конкретная деталь (например Colt Mount) — после снятия возвращается сама WeaponPart и ставится обратно прямым путём;
- UniversalAttachment (например верхняя Picatinny на Mossberg) — Gunworks при снятии возвращает универсальный предмет планки, а при установке преобразует его обратно в weapon-specific `Picatinny_Rail_Up`.

Перед снятием проверяются зависимости. Если на планке стоит прицел/другой дочерний обвес, планка не снимается.

## Штыки

`M5_Bayonet_Attachment`, `K98_Bayonet_Attachment`, `M9_Bayonet_Attachment` зарегистрированы в PreventRemovals, чтобы их нельзя было снять generic vanilla-механикой. Но они не являются встроенными вечными деталями: Gunworks имеет отдельные `ISBayonetAttach` / `ISBayonetRemove`.

Fix 3 распознаёт этот случай отдельно:
- не пишет «Несъёмное»;
- отображает категорию «Штык-нож»;
- снимает через bayonet action и возвращает исходный нож с сохранением condition;
- ставит обратно через bayonet action.

Встроенные штыки вроде SKS остаются permanent/integrated и generic-снятие для них не включается.

## Производительность / безопасность

Не возвращены:
- `getAllItems()` по script database;
- `getCandidateCategories()`;
- отдельный тяжёлый `riskyUI:update()`.

Кандидаты ищутся только в реальном инвентаре игрока (включая вложенные контейнеры) в момент перестройки/открытия нужного слота.
